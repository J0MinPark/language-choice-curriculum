01  /  연구 질문과 새 시작

4언어 표현 선택 · 학습 이력 · 어휘 관계 | v4.0.0 | 2026.09.14

학습 이력은 다국어 표현 선택을 예측하는가?한국어를 먼저 학습한 AI가 영어·중국어·프랑스어를 추가로 배울 때, 표현할 수 있는 능력과 실제 선택을 분리하고 어원·표기·토큰 관계를 함께 검증한다.

핵심 문제와 범위

다른 언어의 표현이 먼저 출력됐다고 기존 표현을 잊었다고 볼 수 없다. 요청하면 각 언어로 답할 수 있는지와, 요청 언어가 없을 때 어떤 등록 표현을 선택하는지를 따로 관측한다. 이번 실험은 일반적인 외국어 숙달이나 사람의 생각을 측정하지 않는다.

언어 습득 이력과 코드스위칭을 연결하는 계산 연구가 이미 있다[R10]. 이번 기여 후보는 단순 언어 혼합 발견이 아니라, 통제된 추가 노출 이력과 어휘 관계가 미관측 개념의 선택 변화를 예측하는지에 있다. 파일럿에서 신규성이나 효과를 미리 확정하지 않는다.

고정하는 것과 하지 않는 것


유지 | 이번 파일럿에서 검증 | 후속 단계로 남김

한국어 → 영어 → 중국어 → 프랑스어 | 실제 4언어 의미 대응·어원 근거·공유 표현 비중 | 인간 기억 원리·교육효과 검증

독립 초기화 4개, 같은 모델 계보 | 요청 산출, 자유 선택, 측정 재현성, 일정 대조 | 대형 모델 전이·모든 언어 순열

어원 / 표기 / 토큰의 분리 | EN–FR 추가 노출 순서의 효과와 집단별 기술 분석 | 복습 최적화·교정 정책·내부 패칭

에듀테크 연결의 위치

장기 목표는 원하는 언어의 표현을 꺼내기 어려운 상태를 예측하는 학습 AI다. 이번에는 AI의 통제 실험으로 가설과 측정 수단을 검증한다. 실제 학습자 로그가 없다는 이유로 이 파일럿을 막지 않지만, AI 실험의 성공을 사람에게 효과적인 연습법이라고 해석하지 않는다.

표기와 권한

[F] 출처가 명시한 사실 · [D] 본연구 설계 · [H] 미검증 가설 · [R] 실제 로그로 확인한 값 · [U] 사용자 보고. 문서의 수량·임계값은 별도 표시가 없으면 [D]다. 이번 v4는 조건부 제한 파일럿을 허용하며, 본시험은 비활성이다. 과거 패키지·모델·보고서를 재사용하지 않는다.

02  /  데이터와 어원 검증

학습 전에 확정할 원천·의미·표현·증거


원천 [F] | 사용 목적 | 접근과 검증의 한계

국립국어원 사전 API [R1] | 같은 한국어 의미의 EN/ZH/FR 표현·정의 연결 | 인증키 또는 적법한 원본 스냅샷 필요. 번역 결측·다의어는 실제 응답으로 확인.

Wiki40B/ko [R2] | 한국어 초기 corpus와 KO-only tokenizer | 공식 train split·원자료 조건·hash 고정. 원천이 한국어라고 외국어 문자열이 전혀 없다는 뜻은 아님.

Wiktextract / Kaikki [R3] | 어원·차용 경로의 검수 근거 후보 | sense 연결과 출처를 사람이 확인. 자동 추출문이나 LLM 설명을 검증 어원으로 취급하지 않음.

의미 정렬과 등록 표현 [D]

연구 개념 ID는 snapshot + target_code + sense_order다. 네 언어의 실제 표현·뜻풀이를 원문과 대조하여 언어당 등록 표현 1개를 고정한다. 대안 표현은 보존하되 결과를 보고 정답에 추가하지 않는다. API 수집 완료는 검수 완료가 아니다.

NFC·공백 정리만 기본 적용한다. 악센트·간체/번체·병음을 자동 통합하지 않는다. 같은 문자열이 두 언어에 쓰이면 공유 표현으로 남긴다. 언어별 선택이 식별되는 집단과 공유 집단의 포함·제외·미확인 비율을 모두 보고한다.

어원과 형태를 분리하는 방법 [D]


변수 | 정의와 처리

역사적 관계 | 차용 확인 / 공유 원천 확인 / 검토 범위에서 별도 경로 / 미확인. 근거 URL·원본 hash·sense·역사 범위·검수자를 기록.

표기 유사성 | NFC 문자 편집거리로 1 - 거리 / 최대 길이. 어원이나 발음의 대용으로 쓰지 않음.

토큰 유사성 | 실제 frozen tokenizer의 표현-only token Jaccard와 길이. 지시·padding·종료 토큰 제외.

주분석 / 한계 | EN–FR을 우선 검수. KO–ZH 등 미검수 쌍은 미확인으로 유지. 어원과 형태가 분리되지 않으면 독립 어원 기여를 주장하지 않음.

자료 gate [D] 60개 검수 개념, 4언어 식별 개념 40개 이상, 그 안의 EN–FR 관련표현 12개 및 검토된 별도 경로 12개 이상. 이는 검정력 수치가 아니라 파일럿 최소 운영안이다. 미달하면 자료 확보를 먼저 해결하며 두 언어로 축소하지 않는다.

검색어 목록은 수집용 설계 목록이며 대표 표본이나 표준 benchmark가 아니다. 의미·어원 검수 승인 전 학습 금지. 합성 시험 데이터를 실제 학습자료로 쓰지 않는다.

03  /  실험 방법 1/2

순차 습득 관측과 습득 후 일정 대조를 구분한다

S. 한국어 기반 형성 후 외국어를 순차 추가

각 독립 root: random INIT → KO corpus/lexical(T0) → EN 추가(T1) → ZH 추가(T2) → FR 추가(T3). 3언어 시점 T2와 4언어 시점 T3를 모두 보존한다. 준비 weights를 복제한 반복은 독립 초기화가 아니다.

초기 설계는 GPT2형 10층·폭512·8head, context256, vocab16384, dropout0. KO train에서만 학습한 byte-level BPE를 고정한다. 실제 파라미터·버전·정밀도·토큰 수를 기록한다. corpus는 최대 200만 model tokens, 각 lexical 단계는 고정 3,000 updates이며 성능 보장이 아니다.

새 언어 target 1/2 + 기존 언어 합계 1/2을 배정하고 active 입력언어와 ANY/requested를 균형화한다. 복습 비율·업데이트·언어 수가 함께 바뀌므로 S는 recipe 변화의 관측이지 순수 언어 수 효과가 아니다. best dev 대신 고정 단계 종점으로 평가한다.

H. 이미 배운 EN–FR 표현의 추가 노출 순서


구간 | A / B 조작과 통제

Mutable 72 round | 개념 pair에 g=+1/-1을 무작위 배정. A에서 한쪽은 EN36→FR36, 다른 쪽은 역순. B에서는 각각 반대로.

고정 anchor | Mutable 2round마다 KO 1round와 ZH 1round를 동일하게 삽입. 두 anchor 언어 각 36회.

공통 tail | 4cycles × (KO, EN, ZH, FR). 각 언어 최종 40회, 개념당 160회. 60개면 branch당 9,600 target 예시.

A/B의 실제 record 내용 전체, 입력·출력·지시별 횟수, anchor/tail, 마지막 target optimizer step, 전체 update 수를 검사한다. round와 update는 다르다. 길이·유효 token 차이와 입력에 우연히 나타난 표현도 기록한다. lexical loss는 예시별 response 평균 후 batch 평균이다.

T3의 model·optimizer·RNG·loader·누적 위치를 모두 복구하고 공통 LR 변환 후 분기한다. 같은 GPU에서 동일 10step A/A′와 연속실행 대 resume를 대조한다[R7]. CPU 수식시험만으로 GPU 재현성을 통과 처리하지 않는다.

해석 범위: 공유 모델에 배정된 전체 일정의 효과다. 첫 외국어 도입 순서, 특정 단어의 독립 직접효과, 어원의 인과효과가 아니다. B36 하나의 파일럿만으로 다양한 학습 이력에 대한 예측 일반화를 주장하지 않는다.

04  /  실험 방법 2/2 · 평가

근거 방법 [F]와 연구 지표 [D]를 구분한다


지표 | 정의와 선행 근거

등록 산출 S / A / C | [R4]의 reverse-dictionary·greedy 첫줄 일치를 확장. S는 등록표현 일치, A는 요청 언어와 양립, C는 등록된 다른 언어 표현. 등록 밖 응답은 별도 보존하며 의미 오류·망각으로 단정하지 않음.

확률 질량 Z / 선택 Q | [R5]의 continuation likelihood를 참고. 전체 canonical 답+종료기호를 점수화한다. 공유 문자열을 한 사건으로 합친 Q/Z는 본연구 정의이며 첫 토큰·길이 정규화 확률이 아님.

신뢰도 | [R6]의 Spearman + wrapper 절대차, Q의 분산·범위·동률·Z. 하나의 수치만으로 전체 측정 타당성을 판단하지 않음.

예측 / 능력 유지 | MAE는 표준 오차[R9]. 본시험 target은 이력 차이 벡터. 능력 동등성은 TOST[R8]로 검사하며 비유의성을 동등성으로 바꾸지 않음.

p(y) = P(canonical tokens(y + newline) | prefix, ANY)Z = 서로 다른 등록 표현 y의 p(y) 합QM = membership(y)=M인 p(y)의 합 / Z

공유 표현은 언어별로 중복 합산하지 않는다. 네 언어가 구분되는 코호트에만 완전한 Ql 벡터를 정의한다. 공유군은 membership 질량으로 따로 보고한다. 낮은 Z에서 높은 Q가 나올 수 있으므로 raw p·logZ·생성 S/A를 반드시 함께 제시한다. 모든 단계의 후보 universe는 네 언어로 고정한다.

주효과와 파일럿 측정 gate [D]

hs,c,l = gs,c (QlA - QlB), 언어별 h의 합=0.EN–FR 대비 r=(hfr-hen)/2. root별 효과, 개념 변동, 어원 집단 대비를 보고한다. 어원은 비무작위 속성이므로 집단 차이를 역사적 원인으로 단정하지 않는다.

T3/KO/RD/dev에서 요청언어별 A가 각각 0.90 이상이어야 한다. 같은 checkpoint·root·개념집합에서 dev1/dev2를 정렬하여 언어별 rho와 절대차를 계산한다. 어느 언어든 rho&lt;0.60 또는 undefined, 절대차&gt;0.15, 어느 wrapper든 Z&lt;0.05 비율이 10% 이상이면 측정 경고로 H를 차단한다. 모두 설계 경고선이며 보편적 기준이 아니다.

분할·불확실성과 미래 예측 검증

독립 단위는 root 초기화다. wrapper·평가 행을 독립 학습 반복으로 세지 않는다. seed 간/개념 간 변동과 split-half 재현성을 구분하며 MAE를 상관으로 나누지 않는다. 향후 초기 편향·최근성 비교군, 이력, 형태, 어원, 상호작용을 같은 회귀기로 비교한다. 어원 family·동의어 cluster를 분리하고 새 개념·새 일정·새 root 성능을 각각 보고한다. 60개 파일럿의 예측 우월성은 확인적으로 판정하지 않는다.

05  /  실행 순서와 판정

잘못된 실행의 재발을 막는 최소 운영 규칙


순서 | 통과 조건 / 멈추는 조건

1. 새 시작 | 전달 해시·CPU 시험 → API 키/적법한 스냅샷. 키 없으면 요청 0회로 차단. 구버전 실행 감사는 하지 않음.

2. 자료와 코드 | 네 언어 의미·어원 검수, 고정 cohort와 config hash, 실제 tokenizer/scorer/전체 상태 재현성 시험. 합성 자료로 승인 대체 금지.

3. 첫 root | 독립 INIT부터 T0~T3 실행. 준비·측정 미달이면 S 자료와 실패를 보존하고 다른 roots/H 확대 금지.

4. 제한 파일럿 | 나머지 예정 roots도 독립 학습. 모두 T3 gate 통과 후 H. 원본 평가→단일 JSON→표·markdown·판정. main은 비활성.

예산 [D/U]: campaign 24 GPUh, root당 6 GPUh 상한. 이전 0.953 GPUh는 사용자 보고 누계로 분리 기입하고 같은 campaign에서 차감한다. 두 GPU의 동시 사용 시간은 합산한다. 새 폴더라도 비용을 몰래 0으로 초기화하지 않는다. 실제 비용·최대 VRAM과 중단 상태를 기록한다.

현재 검증 [R]: CPU 시험 65개 통과(작은 PyTorch 모델의 상태 복구 시험 포함). 실제 사전 payload·의미/어원 QA·완성 trainer·원격 GPU 학습은 미완료다. 작업 환경의 HTTP 시도는 DNS 오류로 실패했다. 이 ZIP은 새 구현과 실행을 위한 명세·참조 도구이며 학습 결과가 아니다.
