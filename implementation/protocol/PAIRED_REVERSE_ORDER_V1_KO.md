# 같은 T0에서 출발하는 역순 1회 — 결과 이후 탐색

2026-09-16 사용자 요청에 따라 정순 seed 추가를 중단하고 역순 일정 1회를 실행한다.
정순 네 seed의 결과를 이미 본 뒤 정한 탐색이며 원래 H/B36나 본시험이 아니다.

## 고정 비교

- seed 선택 규칙: 기존 seed 중 번호가 가장 작은 **4101**. 추가 독립 seed로 세지 않는다.
- 원래 4101 T0 고정 종점의 model/optimizer/scheduler/RNG/loader/progress 전체 상태를
  해시 확인 후 가져온다. source checkpoint와 원래 lineage는 보존하고 새 freeze/code로
  이어지는 import임을 명시한다. model/optimizer/RNG의 의미적 fingerprint 일치를 확인한다.
- 정순: KO T0 → EN T1 → ZH T2 → FR T3.
- 역순: 같은 KO T0 → FR T1 → ZH T2 → EN T3.
- 3000 updates/stage × 3 = 추가 9000 updates. batch32, lr3e-4, 기존 손실,
  train1/train2, 200 updates 진단, 고정 종점 및 후보 표현 4언어를 유지한다.
- 같은 root/stage의 개념·요인 위치 난수를 유지하며 EN/FR의 도입 역할만 바꾼다.
  실제 언어 이름, 뜻풀이, 정답을 바꾸어 부르지 않는다. 미도입 언어는 학습에서 제외한다.
- T1 target KO/FR=1/2씩; T2 ZH=1/2, KO/FR=1/4씩;
  T3 EN=1/2, KO/FR/ZH=1/6씩. 입력 언어·ANY/REQUESTED·문구 균형도 유지한다.

## 해석과 보고

역순 T1~T3에서 총 target 슬롯 수는 KO 88000, FR 88000, ZH 64000, EN 48000이다.
정순은 KO 88000, EN 88000, ZH 64000, FR 48000이다(T0 제외).
따라서 언어별 총노출·최근성·도입순서가 함께 바뀌는 **일정 대비**다.
총노출을 맞춘 순수 순서 효과, 초기화만의 효과, 역순의 seed 분산을 식별하지 않는다.

평가는 같은 KO/RD/dev1/dev2의 지정 산출과 확률 기반 Q/Z가 주 비교다.
기존 확률 합산·종료기호·미등록 처리·임계값은 변경하지 않는다.
중간 단계의 active 요청 언어는 역순을 따른다. 네 후보 표현은 항상 유지한다.
readiness/measurement 실패는 진단 결과로 기록하며 성공으로 바꾸지 않는다.
8문구 평가를 수행하지 않은 점수를 Q8이라고 부르지 않는다.

정순 결과가 보인 것은 고정 일정 내 seed 변동이지, 일정 효과가 없다는 증거가 아니다.
85.0% 하한 및 초기 대비 정확도 감소를 보고한다. 정식 동등성 검증 없이 능력이
완전히 보존되었다고 쓰지 않는다. 한 역순 실행으로 역순 seed 분산을 추정하지 않는다.

## 비용·운영

물리 GPU2 단일 실행, 기존 캠페인24h/root6h 상한과 사용 원장을 그대로 사용한다.
H와 main은 비활성. 자동 추가 학습·역순 seed 확대·best checkpoint 선택 없음.
원자료·평가·단계 종점을 보존하고 기존 중간 상태 정리 규칙을 적용한다.
클라이언트 접속 종료와 독립적으로 실행하지만 서버 전원 종료/재부팅의 자동 복구는 아니다.
